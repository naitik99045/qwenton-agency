================================================================================
1. PRODUCT POSITIONING
================================================================================

qwenton-agents is an AI coworker workspace for business owners, startup founders,
marketing teams, freelancers, agencies, creators, SMBs, and AI builders.

The product helps users create focused AI agents for research, content, documents,
company knowledge, and workflow support. The product should feel practical,
calm, trustworthy, and easy to use rather than overly technical or hype-driven.

Core positioning:

- Give AI a clear role.
- Connect only approved tools and information.
- Assign a real business task.
- Show the activity and output.
- Require human approval before sensitive external actions.

Preferred product language:
- Focused AI agents
- AI coworkers
- Business workflows
- Approved tools
- Company knowledge
- Visible activity
- Human approval
- Early users and honest feedback

Avoid these claims unless verified through evidence and approved for advertising:
- 100x faster
- Guaranteed viral growth
- 100% safe
- Replaces your entire team
- India’s number one AI agent platform
- Zero unauthorized actions
- Guaranteed productivity
- Better than Skydive
- Unlimited AI usage

4. GROWTH ADVANTAGES TO BUILD ON THE EXISTING SYSTEM
================================================================================

4.1 Faster first value
----------------------
Improve the existing landing page and onboarding so a new visitor can understand
qwenton-agents quickly.

Update the existing system to include:
- Clear explanation of AI coworkers.
- Three or four realistic business use cases.
- A safe interactive demo using fictional data.
- A visible human-approval example.
- Clear early-user CTA.
- No requirement to connect private tools for the demo.

The public demo must be protected with:
- IP and session rate limiting.
- Maximum input length.
- Anonymous daily usage quota.
- No private file uploads.
- No external write actions.
- No real customer data.
- No unrestricted expensive model calls.
- Bot protection if abuse appears.

Do not publish an estimated conversion increase unless measured through an actual
experiment.

4.2 Agent templates
-------------------
Add templates inside the existing agent-creation wizard. Templates should create
safe starting configurations, not pretend that a complete autonomous agency has
been created.

Recommended templates:
- Competitor Researcher.
- Social Content Planner.
- Marketing Brief Builder.
- Company Knowledge Assistant.
- Customer Reply Drafting Assistant.
- Weekly Business Summary.

Each template must define:
- Role.
- Instructions.
- Allowed read-only tools.
- Approval requirements.
- Example prompts.
- Output format.
- Usage limits.

4.3 Campaign workspace
----------------------
Add a campaign workspace as an update to the existing agent workspace.

A campaign may combine outputs from several focused agents, but it must not create
unrestricted autonomous activity.

Recommended flow:
1. User describes a campaign goal.
2. Research agent prepares findings.
3. Content agent prepares drafts.
4. Creative agent prepares a visual brief or carousel copy.
5. Operations agent prepares optional scheduling suggestions.
6. User reviews each deliverable.
7. External actions remain separately approval-gated.

Do not use one broad “Approve Entire Campaign” button for all external actions.
Show separate approvals for:
- Research completion.
- Content draft.
- Visual asset.
- Email draft.
- Calendar action.
- WhatsApp message.
- Telegram message.
- Instagram publishing.

4.4 Exportable marketing assets
------------------------------
Add a safe export workflow to the existing marketing features:

- Instagram carousel copy.
- LinkedIn post draft.
- Campaign brief.
- Marketing research report.
- Content calendar.
- PDF or PNG visual export using existing design tokens.

Every export should show whether it is:
- AI-generated draft.
- User-edited draft.
- Approved final.

Do not state that generated content is guaranteed to perform or go viral.

4.5 Mobile-first interaction
----------------------------
Continue improving the existing Telegram integration. Consider WhatsApp only as a
later feature after Meta Business setup, webhook verification, template rules,
consent handling, and rate limits are implemented.

Telegram improvements:
- View assigned agents.
- Submit a task.
- Receive progress updates.
- Review drafts.
- Approve or reject pending actions.
- Receive failure notifications.
- Link every approval to the correct workspace and user.

================================================================================
5. FUTURE FEATURE BACKLOG
================================================================================

The following features are optional future updates. They must not be implemented
all at once.

5.1 Campaign mission mode
-------------------------
Goal: Allow a user to coordinate several focused agents through one campaign view.

First release:
- Sequential or bounded execution.
- Maximum number of delegated subtasks.
- Clear subtask ownership.
- Shared workspace-scoped context.
- Progress timeline.
- User review between phases.

Later release:
- Parallel subtasks where safe.
- Automatic result bundling.
- Cost and token estimate.
- Failure recovery.

Never allow mission mode to bypass approval requirements.

5.2 Embeddable agent widget
---------------------------
Goal: Allow a workspace owner to embed a public, limited agent on a website.

Required protections:
- Explicit public-agent setting.
- Workspace owner approval.
- Public/private distinction.
- Signed widget configuration.
- Allowed origin list.
- Per-IP rate limit.
- Per-workspace quota.
- Maximum message size.
- No private files by default.
- No external write tools by default.
- Abuse reporting.
- Disable and revoke controls.

A “Powered by qwenton-agents” badge may be included as an opt-in growth loop.
Do not make attribution deceptive or impossible to remove from a paid plan unless
that commercial policy is clearly disclosed.

5.3 Voice input and output
--------------------------
Goal: Let users send voice instructions and optionally listen to agent responses.

Requirements:
- Explicit microphone permission.
- Clear recording state.
- Upload size and duration limits.
- Transcription error handling.
- User confirmation before executing a transcribed instruction.
- No external action directly from a voice recording.
- Provider cost limit.
- Audio retention and deletion controls.

5.4 WhatsApp Business Cloud API
--------------------------------
Treat this as a separate integration project, not a simple Telegram copy.

Requirements:
- Meta Business setup.
- Webhook verification.
- Approved templates where required.
- Consent and opt-out flow.
- Message-status tracking.
- User-to-workspace mapping.
- Rate limits.
- Audit logs.
- Separate approval for outbound messages.
- Secure token storage.

5.5 Lead research assistant
---------------------------
A lead research feature may search approved business-data sources and prepare a
prospect list, but it must not become an unrestricted scraper or spam engine.

Allowed first version:
- User supplies a target sector and location.
- Provider-compliant search is used.
- Results include source links and retrieval time.
- Data is used for internal research.
- Agent drafts an outreach message.
- User approves each message or clearly bounded batch.
- Opt-out and compliance guidance is shown.

Do not:
- Scrape Google Maps outside provider rules.
- Harvest personal phone numbers or emails unlawfully.
- Send bulk unsolicited outreach automatically.
- Promise leads or revenue.
- Hide the source of business information.

5.6 Voice and carousel content tools
------------------------------------
Add these only after the core agent and approval systems are reliable.

The tools must support:
- Draft state.
- User editing.
- Visual preview.
- Attribution where required.
- Provider usage limits.
- Asset deletion.
- Approval before publishing.
